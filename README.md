# 재난하늘119 — 재난 긴급 항공출동 판단 시스템

상황실 **운항관제 담당자**가 출발지(119항공대) → 경유지(현장) → 목적지(병원)를 입력하면, 헬기와 구급차(현장→병원) 중 어느 쪽이 빠른지 비교하고, 경로·출발지·목적지의 기상과 항공고시보(NOTAM)를 모아

**④ 임무브리핑**: 첨부 양식(구조·구급·업무지원)과 같은 구성으로 출동 정보를 메신저에 미리 알리는 전송문을 만든다. 장소 칸에서 주소·장소명을 검색해 고르면 `주소 / 명칭(좌표)`가 바로 입력되며(십진수·도분·도분초 선택), [복사]로 붙여넣는다.
**「119항공대 운영 규정」 제21조(비행제한)** 기준으로 **임무판단 조언**과 근거를 보여 줍니다.

> 본 시스템은 **조언용**입니다. 운항 여부의 최종 결정은 출동 지휘 담당자(항공 통제관)와 조종사(기장)가 합니다(제21조① 단서, 제24조②).

## 1. 준비 (최초 1회)

1. **파이썬 3.9 이상**만 있으면 됩니다. 추가 설치(pip)는 필요 없습니다.
2. `config.local.example.json`을 `config.local.json`으로 복사하고 키를 입력합니다.
   ```json
   { "kmaAuthKey": "기상청 API허브 인증키", "kakaoJsKey": "카카오 JavaScript 키" }
   ```
   - `config.local.json`은 이 PC에만 둡니다. 공유·배포하지 않습니다.
3. **카카오 개발자 콘솔** → 내 애플리케이션 → 플랫폼 → Web → 사이트 도메인에 `http://localhost:8000`을 추가합니다.
4. (선택) 출발 기지 목록: `config.json`의 `"bases"`에 넣으면 드롭다운에 나타납니다.
   ```json
   "bases": [ { "name": "OO 항공대", "lat": 37.0000, "lon": 127.0000 } ]
   ```


## 1-1. 웹 배포 (Vercel, 링크로 공유)

사용자는 **링크만 열면** 됩니다(설치 없음). 관리자가 한 번만 설정합니다.

1. 이 코드를 GitHub 저장소에 올립니다.
2. [vercel.com](https://vercel.com) → **Add New… → Project** → 저장소 **Import**
   - Framework Preset: **Other** (빌드 설정은 비워 둠)
3. **Environment Variables**에 입력합니다.
   | 이름 | 값 |
   |---|---|
   | `KMA_AUTH_KEY` | 기상청 API허브 인증키 |
   | `KAKAO_JS_KEY` | 카카오 JavaScript 키 |
   | `ACCESS_CODE` | 기관 공용 접속코드(비워 두면 누구나 사용) |
4. **Deploy** → 나온 주소(예: `https://heli-wx.vercel.app`)를 카카오 개발자 콘솔의 Web 사이트 도메인에 추가합니다.
5. (NOTAM 공유 저장) 프로젝트 **Storage** 탭 → **Create Database → Upstash for Redis**(무료) → 이 프로젝트에 연결 → **Redeploy**. 환경변수 `KV_REST_API_URL`·`KV_REST_API_TOKEN`이 자동으로 추가됩니다.
6. 링크와 접속코드를 공유합니다.

- 키는 Vercel 환경변수에만 있고 코드·GitHub·브라우저에는 나가지 않습니다.
- 기상 응답은 Vercel 캐시에 1~5분간 공유되어 여러 명이 써도 기상청 호출이 늘지 않습니다.
- 조회 이력은 각 브라우저에 저장되며 화면의 **[이력 CSV 내려받기]**로 받습니다.
- 환경변수를 바꾼 뒤에는 Vercel에서 **Redeploy**해야 반영됩니다.

## 2. 로컬 실행 (인터넷 장애 대비용)

```bash
python run.py
```
브라우저가 자동으로 `http://localhost:8000`을 엽니다. 종료는 창에서 `Ctrl+C`를 누릅니다.

- 시험 자료로 화면만 보기: `python run.py --mock`
- 포트 변경: `python run.py --port 8080` (이 경우 카카오 도메인도 같이 등록해야 합니다)

## 3. 사용 순서

1. **좌표 형식**(십진수 / 도·분 / 도·분·초)을 고릅니다. 바꾸면 모든 좌표칸이 그 형식으로 다시 표시됩니다.
2. 출발지·목적지: 장소 검색 후 **Enter(첫 결과 선택)** 또는 목록 클릭, 지도 클릭("지도 클릭 → 이 지점" 선택), 또는 **좌표칸에 직접 입력**합니다.
   - 도·분·초는 `37 33 30, 126 47 26`, `37°33'30"N 126°47'26"E`, `373330N1264726E` 모두 됩니다.
3. 자주 쓰는 지점은 **★ 주요지점**에 저장해 두고 검색해서 씁니다(주요지점 상자에서 "현재 지점에서 가져오기" 또는 좌표로 추가, 최대 500곳, 공유 저장). 카드의 장소 검색에도 ★로 함께 나옵니다.
4. 필요하면 **[+ 경유지 추가]**(최대 5개). 경유지마다 체류시간(급유·환자 인계 등)을 넣을 수 있고 ▲▼로 순서를 바꿉니다.
5. 출발 예정시각, 순항속도(기본 120kt)를 확인합니다. 주간/야간과 육상/해상은 자동으로 정해지고 바꿀 수 있습니다.
6. [xNotam 열기]로 조회한 결과를 **NOTAM 칸(①②③④…)에 붙여넣고 [저장]**합니다.
   - 웹 배포에서 공유 저장소를 연결하면 상황실 전원이 같은 칸을 봅니다(교대 인수인계). 칸 제목에 번호·종류·종료시각이 요약되고, 기간이 끝난 NOTAM은 "만료"로 표시됩니다.
   - 저장하지 않은 내용도 [판단 실행] 시 함께 판정합니다.
7. **[판단 실행]** 결과 화면에서 **[판정 기준 보기]**로 "규정 조문"과 "시스템 설정값(규정 아님)"을 구분해 확인할 수 있고, 야간·해상이면 **제22조 특수조건 확인표**가 나타납니다(체크하며 확인, 판정에는 반영되지 않음). 풍속은 m/s와 kt를 함께 보여 줍니다.을 누릅니다. 종합 판정, 근거 표, 바람, NOTAM, 보고문이 나옵니다. **[보고문 복사]**로 상황 보고에 씁니다.

### 사용 편의 기능
- 출발·도착 바꾸기, 최근 조회 경로 불러오기, 출발 예정시각 [지금], Enter / Ctrl+Enter 실행, 경유지 복제
- 결과 맨 위 한 줄 요약, 기상 자료 수신 상태(방금·N분 전·실패), 수신 실패 시 [다시 시도], 20분 지난 판단 재실행 안내
- 육상/해상 자동 판별: 카카오 행정구역 조회 + 내장 해안선(Natural Earth, 퍼블릭 도메인)으로 육지에서 약 3km 이상 떨어진 바다 위 점이 하나라도 있으면 해상 기준(더 엄격) 적용
- 비행금지·제한구역(AIP ENR 5.1: R-75 수도권, P-73 서울, P-518 휴전선 일대·서부·동부)을 지도에 상시 표시하고, 경로가 통과하거나 3NM 이내로 근접하면 "주의 + 허가 필요"로 안내 (좌표는 `web/airspace.js`, 개정 시 교체)
- 지도 종류 전환(일반 / 항공사진), 선택 기억. 항공사진 위 지명은 [지명] 버튼으로 끄고 켬, 사진이 없는 확대 단계는 낮은 단계 사진을 키워 대체(최대 21단계). [항공사진]은 환경변수 `VWORLD_KEY`(국토교통부 브이월드 인증키, 도메인 등록)가 있을 때만 나타나며 헬기장 확인용 고해상도 항공사진 위에 경로·NOTAM·비행금지구역을 같은 좌표로 표시
- NOTAM에 완충구역(BUFFER ZONE)이 있으면(예: 금지 반경 3NM + 바깥 10NM) 원문을 읽어 금지구역(빨강)과 완충 외곽(주황 점선, 중심에서 13NM)을 그리고, 경로가 완충구역을 지나면 "완충구역 통과 — 사전조율·승인 필요"로 안내. 폭은 Q선 반경과 비교해 해석을 검증하고 원문 예외(EXC …)도 표시
- 지도의 NOTAM은 구역(빨간 원)과 함께 판정에서 "근접"으로 보는 **근접 경고권**(반경+5NM, 주황 점선)도 표시
- 지도 위 위치·좌표 찾기: 장소명·주소·좌표를 검색하면 그곳으로 이동해 핀을 찍고 좌표를 십진수·도분·도분초 세 가지로 모두 보여 주며(각각 [복사])·[출발지로]·[경유지로]·[목적지로]·[주요지점 저장]을 지원. 판단 실행 후 지도를 누르면 지점은 바뀌지 않고 누른 곳의 좌표 카드만 표시
- 결과 항목 접기·펼치기, 글자 크게, 야간 화면, 사용법 안내, 폰에서 [판단 실행] 하단 고정
- 주요지점: 종류 분류·검색·더 보기, 엑셀(CSV) 내려받기·불러오기

## 4. 판정 기준

| 구분 | 시정 미만 시 제한 | 운고 미만 시 제한 |
|---|---|---|
| 주간 육상 / 해상 | 3,200m / 4,800m | 1,000ft / 1,500ft |
| 야간 육상 / 해상 | 4,800m / 4,800m | 2,000ft / 2,000ft |

| 항목 | 🔴 규정상 비행제한 | 🟡 주의 | 근거 |
|---|---|---|---|
| 시정·운고 실황 (METAR·ASOS) | 기준 미만 | 기준의 1.5배 미만 | 제21조①1·2 |
| 공항 예보 TAF (출발~도착+30분) | 기본 예보가 기준 미만 | TEMPO·PROB 미달 | ①3 |
| 기상특보 | 태풍·강풍·풍랑·대설·호우 (경로 시군구 일치) | 같은 시·도 특보, 기타 특보 | ①4 |
| 낙뢰 (최근 30분, 경로 20km) | — | 경로 변경 검토 | ② |
| 저고도 중요기상예보(SIGWX) | — | 경로가 착빙·난류·산악차폐·저시정 등 구역 통과 | ④⑥ |
| NOTAM (D 시리즈) | — | 경로 통과/5NM 이내 + 발효 | 제15조⑤ |
| 바람 | **판정 안 함**: 평균·순간최대·추세만 표시 | | 기종별 교범 |

- **ASOS 운고**는 층별 구름 자료가 없어 "중하층 운량 6/10 이상"일 때 최저운고를 운고로 근사합니다(규정 정의는 가장 낮은 구름층이 5/8 이상 덮인 경우). 상층운만 많은 날의 불필요한 제한을 줄이고, 중하층 운량이 없는데 전운량이 6/10 이상이면 "자료없음"으로 표시합니다. 근거 표에 전운량·중하층 운량을 함께 보여 줍니다.
- 자료가 없거나 오래되면(METAR·ASOS 90분, AWS 20분 초과) **⚪ 자료없음**으로 표시합니다. 절대 "가능"으로 처리하지 않습니다.
- 출발지·목적지의 시정 또는 운고 자료가 없으면 종합 판정도 ⚪입니다.
- 기준값은 `config.json`의 `limits`에 있습니다. 규정이 개정되면 이 값만 고치면 됩니다.

## 5. 장애 시

- 기상청 API 하나가 실패해도 나머지는 계속 판정합니다. 실패한 항목만 ⚪로 표시하고, 직전 자료가 있으면 "N분 전 자료"로 씁니다.
- 프로그램이 동작하지 않으면 화면 하단 **수동 확인 링크**(xNotam, 항공기상청, 기상특보)로 업무를 계속합니다.

## 6. 알려진 한계

- NOTAM은 자동 수집하지 않습니다(xNotam 공개 API 없음). 붙여넣기 방식입니다.
- 경로는 출발지·경유지·목적지를 차례로 잇는 직선 구간입니다.
- 특보구역은 행정구역 이름으로 맞춥니다. 산지/평지처럼 쪼개진 구역이나 해상 특보구역은 정확히 맞추지 못할 수 있어 🟡와 원문 확인으로 보완합니다.
- **저고도 중요기상예보(SIGWX)**: 기상청 응답(XML)의 구역 위치는 웹지도 투영 좌표라 위경도로 변환해 사용합니다(실제 응답의 화면 모서리가 위도 39.0°/27.5°, 경도 121.0°/135.0°로 정확히 계산됨을 확인). 착빙·난류·저시정·지상풍 구역을 경로와 비교하고(저층 `low`만, 중·고층은 제외), 구역 고도(예: FL060 이상)와 0℃ 고도선을 함께 안내합니다. 구역의 고도는 비행고도와 비교하지 않으므로 담당자가 확인합니다. 형식이 달라지면 결과 화면의 [저고도 SIGWX 원문 보기 → 구조 요약]으로 확인합니다.
- 일출·일몰은 천문 계산식(NOAA 방식, 오차 1~2분)입니다. 공식값은 한국천문연구원 출몰시각 자료로 확인하세요.
- NOTAM 공유 칸은 접속코드를 아는 사람 누구나 수정·삭제할 수 있습니다(마지막 저장이 반영).

## 7. 실제 응답 형식 점검

기상청 응답 형식이 예상과 다르면 일부 항목이 ⚪로 나옵니다. 아래 명령으로 점검합니다.
```bash
python server/check_api.py
```
출력(인증키는 `****`로 가려짐)을 복사해 전달하면 해석기를 맞출 수 있습니다.

**PC가 없을 때 (휴대폰 브라우저로 확인):** 아래 주소의 `{KEY}`를 인증키로 바꿔 열고, 화면 내용을 **키를 지운 뒤** 전달합니다.
- 지상관측(ASOS): `https://apihub.kma.go.kr/api/typ01/url/kma_sfctm2.php?tm=&stn=108&help=1&authKey={KEY}`
- AWS 매분: `https://apihub.kma.go.kr/api/typ01/cgi-bin/url/nph-aws2_min?tm2=&stn=400&disp=0&help=1&authKey={KEY}`
- 특보현황: `https://apihub.kma.go.kr/api/typ01/url/wrn_now_data.php?fe=f&tm=&disp=1&help=1&authKey={KEY}`

## 8. 보안·데이터

- API 인증키는 PC의 `config.local.json`에만 저장되고, 브라우저 화면으로 전달되지 않습니다.
- **전송·화면 보안**: 모든 응답에 보안 헤더를 붙입니다(CSP로 스크립트 출처를 자기 사이트와 카카오로 제한, 다른 사이트에서 화면 삽입 금지, MIME 추측 금지, 위치·카메라 등 권한 차단). 카카오맵 SDK가 내부에서 `eval`을 쓰기 때문에 `'unsafe-eval'`만 허용하고, 스크립트의 `'unsafe-inline'`은 허용하지 않습니다. CSP는 감시 모드로 실사이트 위반 0건을 확인한 뒤 강제 모드로 전환했습니다.
- **접속코드 보호**: 같은 IP에서 10분 안에 10번 틀리면 10분간 잠깁니다(맞는 코드도 거부, 화면에 남은 시도 횟수 표시). 다른 사이트에서 몰래 보내는 쓰기 요청(저장·삭제)은 출처(Origin)가 다르면 거부합니다. 코드는 길고 무작위로(10자 이상) 정하세요.
- 한계: 접속코드는 상황실 공용 1개이며 사용자별 권한 구분은 없습니다. 개인별 인증(기관 SSO 등)은 향후 과제입니다.
- 개인정보를 수집하지 않습니다. 처리 데이터는 공개 기상·항공정보뿐입니다.
- 조회 이력(로컬: `logs/history.csv`, 웹: 각 브라우저)에는 시각·출발·목적지·거리·종합판정만 기록합니다.
- 공용 누적 사용량: [판단 실행]마다 시각·출발·경유·목적지·거리·종합판정만 공유 저장소(Upstash)에 쌓이고(개인 식별정보 없음), 화면 상단 배지와 결과 패널에 누적·오늘·사용일수·최근 7일이 표시됩니다. [공용 누적 이력 CSV]로 증빙을 내려받습니다.
- 웹 배포 시 접속코드(`ACCESS_CODE`)로 사용을 제한합니다. 기상 자료 자체는 공개 정보입니다.
